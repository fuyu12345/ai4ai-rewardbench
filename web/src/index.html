How does AI judge AI research?

AI for AI (AI4AI) puts models to work on kernel optimization, ML engineering, scientific discovery, and training algorithms. Each task calls for choosing a promising approach under specific goals and resource constraints.

RewardBench tests models’ research preferences across these tasks using existing agent artifacts and evidence—without rerunning heavyweight training or GPU experiments.

Each pair contributes equally. The model predicts A, B, or tie against a frozen label, following the task-specific decision rule.

What do these results establish?+

A snapshot of preference judgment on a curated development collection. These are historical labels, not an independently sampled hidden test set. They do not establish a general model ranking.

How are the two modes evaluated?+

Reasoning receives all public materials inline. Agent uses read-only tools constrained to the public manifest. Neither mode receives organizer labels. Runs use fixed A/B order. Sol uses xhigh reasoning effort and Opus 5.5 uses high; the other displayed settings use their recorded defaults. No position-swap study is claimed.

Which runs are compared?+

Every configuration uses three scheduled repeats per task, with the documented Claude Sonnet exception. Sol xhigh, Terra default, and Opus 5.5 high each have 405 valid results across all 135 tasks. Repeats are included in full, without selecting the best run. Original attempts and recovery batches are grouped into one result per model and repeat. Different effort settings and recovery budgets still affect comparisons.

What counts as resource use?+

Reported input/output tokens include failures, repairs and recovery attempts. Cached input is a subset of input. Agent model turns, tool rounds, tool calls and API attempts are distinct; missing usage is not zero.

What are the known limitations?+

Labels are imbalanced. Two source-code cases retain performance self-reports. Recovery budgets differ, including extended hy4 retries. Gemini signature compatibility handling and answer parsing repairs are documented. The single Claude Sonnet refusal is excluded only under the documented exception.
